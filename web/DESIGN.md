# DESIGN.md — rekord_graph の見た目の正本

「なぜこの色・この字なのか」を人間が読むための正本。
値の正本は `src/app/globals.css` のトークン。**画面側で色・余白をハードコードしない。**

---

## コンセプト: CDJ の計器パネル

Web アプリを暗くしたものではなく、**機材の読み取り面**として作る。
隣に置かれるのは CDJ と DJM であって、他の Web サイトではない。

使う状況が設計を決めている:

- **暗い。** クラブの照明下 → **ダーク固定**（ライトテーマは作らない）
- **急いでいる。** 次の曲に入る数十秒 → スクロールなしで候補が見えること
- **片手。** もう片手はジョグかフェーダー → タップ領域 44px
- **見るものは決まっている。** 「どのパッドを押すか」が9割

## 情報の優先順位（レイアウトの根拠）

```
曲名  >  キュー記号(A〜P)  >  キュー名  >  曲中の位置  >  修飾(ループ/小節)  >  コメント
```

**曲名を出す所には BPM を添える。** グラフのパネル・チェーン・入力の一覧・カード・
一覧のカード、どこでも同じ。次に行ける曲が分かっても、テンポが分からなければ
「その繋ぎが今できるか」を判断できない（曲名の次に見るのが BPM）。
数字は等幅・`tabular-nums`・`fg-subtle` で、曲名より一段弱く置く。

## 記憶に残る一点: タイムライン

各トランジションで、**曲を1本のタイムラインとして描く**。
`2:36.133` という数字だけでは体感と結びつかないが、
「曲の終盤で抜けて、相手の頭から入る」が絵で分かると一目で掴める。

**振幅は描かない。** 波形データを持っていないので、それらしく描くと嘘になる。
出すのは実データだけ = 曲の長さ・キューの位置・1分ごとの目盛り。
（このために rekordbox の `Length` を取り込み、Notion に「長さ秒」を追加した）

## パフォーマンスモード（本番中）

**プレイ中に開くための、書き換えられない状態。** 使う状況が理由そのもの:
片手・暗所・急いでいる。その状態で画面に編集の入口（繋ぎを追加・編集・星・配置の保存）が
並んでいると、誤爆した瞬間に**本番中に記録が書き換わる**。

- 編集の入口には `data-edit` を付ける。`[data-perf="on"] [data-edit]` が消す
- 読むもの（曲名・キュー・タイムライン・繋ぎの一覧・配置パターンの切り替え）は**残す**。
  畳むのは「書く」ものだけ
- **指が当たっただけで書き込まれるものは、CSS では止まらない。**
  グラフのノードは触れると動き、1.2秒後に配置が保存される → 本番中はドラッグを
  地図の移動として扱い、保存も待機中のものごと捨てる
- 本番中は**画面上端に琥珀の細い線**を出す。今どちらのモードかを一目で分かるように
- 切り替えは常設のナビの中に置く（グラフを全画面で見ている最中でも押せる位置）

## ループのキュー

rekordbox でループになっているキュー（実機に**終わりの位置**が入っているもの）は、
記号とキュー名のすぐ隣に「ループ」の札を出す。押し方が変わる情報なので、
曲ページ・グラフ・チェーン・入力のどこで見ても同じように出る
（文字列で出す所は `cueLabel` が唯一の正本）。

**キュー名が既に「ループ」と言っているなら札は出さない**（`1サビ終ループ` に
「ループ」を足すと同じことを2回言うだけ）。キュー名が正、が全体の前提。

**小節数は出さない。** BPM から割り出すとキュー名と食い違う（実データの
`ループ_ドゥドゥドゥ_8小節` は 2.7 秒 = 8小節にならない）。長さが要るときは秒で出す。

## 色

rekordbox / CDJ の色をそのまま持ち込む。機材と同じ意味で読めるように。

| トークン | 役割 |
|---|---|
| `bg` / `surface` / `surface-2` / `elevated` | 面の階層。純黒にしないのは暗所で目が痛むため。青緑に寄せた黒 |
| `fg` / `fg-muted` / `fg-subtle` | 文字の3階層。優先順位をそのまま明度で表す |
| `hot` | **ホットキュー = 琥珀。** 機材のパッドと同じ色 |
| `accent` | 波形・現在地 = シアン |
| `route` | **選んだ曲からの道筋 = 赤。** 選択で周りを沈めても、道筋だけは沈めず通す |
| `route-start` / `route-end` | **ルート強調（琥珀）の始点 = 黄緑 / 終点 = 朱。** 琥珀から色相を両側へ少しずらした色 |
| `incoming` | **選んだ曲に入ってくる線 = 藤色。** 出ていく線（シアン）と向きを取り違えないため |
| `warn` / `ok` | 要確認 / 正常 |

**BPM や Key で色分けはしない。** 色が増えるほど暗所で一目で読む妨げになる。
色は「ホットキュー」「現在地」「道筋」「異常」の4つの意味にだけ使う。
（ルート強調の両端の黄緑・朱は新しい意味ではなく「道筋」の一部 = どちらが始まりでどちらが終わりか、だけを言う）

### グラフ（ネットワーク表示）の色

**既定はどのノードも矢印も同じ色・同じ明るさ。** 常時どこかが光っていると、
本当に見たいものを探すときに邪魔になる。琥珀で光らせるのは、
**「ルート強調」を押したときだけ**（＝全体の最長ルートを見せてくれと頼まれたとき）:

| ボタン | 何が起きるか |
|---|---|
| （既定） | 全部出す。全部同じ色 |
| ルート強調 | 全部出したまま、最長ルートだけ琥珀。**始点は黄緑（`route-start`）・終点は朱（`route-end`）** |

（「ルート以外を消す」Solo もあったが、使われないので外した）

**ルートの両端だけ色をずらす。** 琥珀一色だと、光った列のどちらの端から読めばいいかが
分からない。両端の色は琥珀から色相を両側へ少しずらしたもの（黄緑 → 琥珀 → 朱）で、
「ルートの一部」とは読めたまま、始まりと終わりが一目で分かる。丸は一段濃く・暈しは一段大きくする。
色を載せるのは丸だけで、線は琥珀のまま（向きは矢羽根が示している）。

ホバー/選択で近傍以外を沈めるのと、検索一致を光らせるのは残す。
これは常時の飾りではなく、その瞬間の操作に対する返事だから。

**選んだ曲とつながっている曲・線ははっきり出す**（＝現在地の色）。
沈めた曲との差が弱いと「で、どこに行けるの？」が読めない:
線は太く（1.2 → 2）、つながっている曲は丸をシアン寄りにして
ラベルを `fg-muted` → `fg` に上げる。ただし**道筋（赤）・ルート（琥珀）と重ねない** —
同じ丸に2色の暈しが乗ると濁って、どちらの意味も読めなくなる。

**その線は向きで色を分ける。** 出ていく（ここから行ける）= `accent` シアン、
入ってくる（ここに入ってこれる）= `incoming` 藤色。矢羽根は向きを示すが、
線が密なところやズームアウト時には一本ずつ追う羽目になる。DJ 中に要るのは
「この曲の次に何が置けるか」であって、色で二分できれば読む手間が要らない。
色を増やすのはこの2値に限る — 選択中しか出ない色なので、既定の画面は今まで通り単色のまま。
**パネルの「ここから行ける / ここに入ってこれる」の見出しも同じ色**にして、
凡例を読まなくても色と向きが結び付くようにする。
色を載せるのは線だけ。丸は片方向に決められない（両向きの隣がある）ので触らない。

**矢印の向きは、線の途中（終点寄り60%）の矢羽根で示す。**
終端の矢先はノードの根元に埋もれ、ズームアウトで潰れて向きが読めなかった。
矢羽根は `/zoom倍率` で描いて**画面上の大きさを一定に保ち**、線より一段はっきり出す
（向きが要点なので）。短い線では線の長さに合わせて縮める — はみ出した矢羽根は向きが逆に読める。

**選んだ曲から繋がっていく道筋（「最大N曲」の実体）は赤（`route`）で通す。**
選択は近傍以外を沈めるが、道筋まで沈むと「ここからどこまで行けるか」が読めない。
だから道筋のノード・線だけは沈めずに赤で出す。1ホップ目はシアン（返事）と重なるが、
赤を勝たせる — 追うべきは道筋だから。

### 曲名は「曲名 (リミックス)」

rekordbox の原題はファイル名由来で読めない（`NOHSHOH_SAKURETSU_GIRL_(Marble_Remix)_final_v2`）。
DJ 中に要るのは **どの曲か** と **どのリミックスか** の2つだけなので、そこだけ出す
（`脳漿炸裂ガール (Marble Remix)`）。原題は検索対象としては残す。

**出した名前は `…` で刈らない。** 長いものは折り返す。
判別できない名前を並べるくらいなら、行が増える方がまし。

### グラフの配置

ノードは点ではなく **ラベルまで含めた箱**。曲名が長いので、点として詰めると必ず文字が重なる。
力学で繋がりの形を作ったあと、箱の重なりを「重なっているぶんだけ」押し分けて解く。

**繋ぎのある曲だけで力学を回し、繋ぎの無い曲は下に整列させる。**
混ぜて回すと、見たい構造（繋がっている数十曲）が孤立曲に押しやられて小さくなる。

## タイポ

- **Archivo** — Latin と見出し。工業的で角が立っており、機材のシルク印刷に近い
- **IBM Plex Mono** — 数字・キュー記号・時刻。A〜P が横幅で揺れると視線が定まらないので等幅は必須
- **日本語はシステム（ヒラギノ）。** 和文 Web フォントは重く、ブースの回線で落ちると困る
- ラベルは小さく・字間を広く・大文字（`.label`）。機材のパネル表記の作法
- 最小 13px。暗所でそれ以下は読めない

## 質感

のっぺりした暗い面は安っぽく見えるので、深さを作る:

- 全面に薄い**グレイン**（opacity 0.035）
- 画面上部にごく弱い**発光**（自発光ディスプレイの感じ）
- カードは上端に内側ハイライト＋落ち影
- ホットキューのパッドは上端ハイライトで**押せるものに見せる**

## モーション

読み込み時にカードを上から順に出す（40ms ずつ）だけ。視線の順序をつくるのが目的。
**それ以外は動かさない。** 暗所で動くものは邪魔になる。
`prefers-reduced-motion` では全部止める。

## グラフ画面（Obsidian × MixTree）

グラフは「読む画面」ではなく「探索する画面」。作法は Obsidian のグラフビューに合わせる:

- **全画面キャンバス。** 枠の中の図ではなく、画面そのものが地図
- 力学レイアウト。ただし**収束はマウント時に同期で回し切る**
  （待ちゼロ・同じデータなら毎回同じ絵・非表示タブで rAF が止まっても壊れない）
- ホバー/選択で**近傍以外を沈める**。読み方は「消す」であって「増やす」ではない
- MixTree から借りた Solo（最長ルートだけに畳む）と Depth（N ホップ絞り込み）は、
  付けたが使われず、ボタンが増えるだけだったので消した
- **スマホの左上に常に出すのは「ネットワーク / ツリー / グラフ内を検索」だけ。**
  ルート強調・まとめて移動・未接続も表示・配置パターンは「表示・配置 ▼」の引き出しに入れる
  （出しっぱなしだと画面の上半分がボタンで埋まり、地図が見えない）。
  引き出しの中で既定から変えているものがあれば、閉じていても取っ手に琥珀の点を出す。
  保存の失敗表示は引き出しの外に置く（閉じていても気づけるように）。
  PC（md 以上）は余裕があるので引き出しにせず常に出す

## ナビゲーション

- PC = 左レール（Obsidian の作法）、スマホ = 下タブ。**どの画面からも1タップで移動できる**
- 現在地はシアン + 左端のインジケータで示す
- **下タブは画面の最下端に貼り付けない。** 最下端は iOS のホームインジケータと
  下スワイプのジェスチャ帯で、そこに置いたボタンは1回目のタップを system に吸われる。
  高さの正本は `--nav-h`（= 56px + `max(safe-area-inset-bottom, 12px)`）。
  下タブ自身・グラフのキャンバス（`bottom-[var(--nav-h)]`）・各ページの下余白（`pb-nav`）が
  すべてこの1つの値を見る（別々に書くと必ずズレて、重なるか隙間が空く）

## 評価（星）はその場で押せる

繋ぎの良し悪しを思い出すのは練習中で、そのとき見ているのはグラフか曲ページ。
そこから入力画面へ戻らせない = **星は表示されている場所でそのまま押せる**（`RatingPicker`）。

- 押した瞬間に見た目を変え、失敗したときだけ戻す（保存待ちで固まらせない）
- 同じ星をもう一度押すと評価を外す
- **カードやリンクの中に入れない。** 操作要素の入れ子はタップが行き先に吸われるので、
  カードは「枠 + リンク + 星の行」の3層に割る

## 繋ぎの追加は、気づいた場所から始める

星と同じ理屈。「ここ繋がるな」と気づくのは曲ページかグラフを見ている最中で、
そこから入力画面へ手ぶらで飛ばすと、着いた先でまた同じ曲を検索する羽目になる。

- 曲ページ・グラフ（ネットワーク／ツリー両方）の選択パネルから
  **`/new?from=<曲>` / `/new?to=<曲>`** で開く。
  着いた時点でその曲は入っていて、次に押すのはキューのパッド
- ボタンは「繋ぎを追加」の見出しの下に **「この曲から →」「← この曲へ」** の2つ。
  320px の脇では長い文言が折り返して2行になるので、向きだけを短く出す
- **向きは2つ出す。** どちらの画面も「行ける先」と「入ってこれる元」を並べて見せているので、
  片方だけだと逆向きを入れたいときに使えない
- **入口はどれも控えめに。** 曲ページの主役は「次に行ける曲」、グラフの主役は地図。
  例外は繋ぎが1本も無い曲で、そこは他に出すものが無いので琥珀の主ボタンにする
  （その曲では脇の「この曲から →」を消す。同じ行き先のボタンを1画面に2つ置かない）
- 入力画面そのものは1つのまま（グラフの中にフォームを出さない）。
  繋ぎを入れるのは DJ 中ではないので、画面が変わって困る場面ではない

## やらないこと

- ライトテーマ / 派手なアニメーション / グラデーションの多用（暗所で滲む）
- 実データに無いものを「それらしく」描くこと（波形の振幅など）
