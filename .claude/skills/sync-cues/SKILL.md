# sync-cues — rekordbox → Notion 📍Cues の同期

キューは頻繁に編集される。「ズレを直して」は繰り返し来る依頼なので、毎回この手順を踏む。
前提は CLAUDE.md の「キュー名が正、アルファベットは信用しない」。照合は **キュー UUID**、作り直しは **位置(ms)** で結び直す。

## 手順

1. **差分を出す（何も書かない）**

   ```bash
   ./.venv/bin/python tools/sync.py --dry-run
   ```

   先頭の `作り直し N件 / 変更 N件 / 削除 N件 / 追加 N件` と、各項目を読む。

2. **削除を必ず精査する。** 削除は Notion の行をアーカイブするので、その行を参照している 🔀Transitions が壊れる。
   作り直しで結び直せず繋ぎから参照されている行は、sync が自動で「削除(保留)」にして `--yes` でも消さない
   （2026-09-22 から）。それでも「どの繋ぎが、どのキューに付け替わるべきか」を人に聞くのはこの手順の仕事。
   記号を判定できないホットキュー（Kind=4）は同期されず、先頭に ⚠ で出る
   - 同じ曲に「追加」があるなら、ほぼ作り直し（消して打ち直した / メモリーキュー→ホットキュー変換）。
     位置(ms)・キュー名・記号を見比べて、同一キューと判断できるか確認する
   - 結び直しの決め手は `tools/sync.py` の `rekey()` の順: ①位置+キュー名 ②同名複数なら記号 ③位置が一意 ④位置+名前の前方一致 ⑤キュー名が一意。
     どれにも当たらず、かつ人の目には明らかな対応があるなら、**決め打ちせず `rekey()` に段を足して再実行**する（一度きりの手当てにしない）
   - 削除が Transitions から参照されているかは、🔀Transitions を `Fromキュー`/`Toキュー` の relation で舐めて確認する
     （`notion_api.query_all(CONFIG["transitions"])`）。参照あり＆結び直せないものは**消さずに**人に見せる
   - **追加が無い削除**（同じ位置に別のキューが残っていて、重複していた方を消した形）は sync では結べない。
     参照があれば、繋ぎの `Fromキュー`/`Toキュー` を **同じ位置(ms)の生き残り行**に PATCH で付け替えてから削除を通す
     （2026-08-22 ループザルーム「1サビ終受け」→「1サビ終受」で実施）。位置が一致しないなら付け替えず人に聞く

3. **新曲は「曲追加」として 🎵Tracks の行も sync が作る**（rekordbox の曲名・別名・BPM・Key・長さ・パス）。
   その曲のキュー追加より前に並ぶので、そのまま通してよい。

4. **記号の変更（★）は DJ 中に押すボタンが変わるので最重要。** 数が多くても全件 rekordbox 由来の値なので、そのまま通してよい。
   「ループ: ふつうのキュー → ループ」は実機の OutMsec 由来。`BeatLoopSize` は見ない

5. **書き込む。** 一括書き込みの前に **rekordbox を終了させる**のが建前（投入中にキューが書き換わると古い UUID が残る）。
   自分で実行してよい（本人が許可済み。`dangerouslyDisableSandbox` が要ることがある）:

   ```bash
   ./.venv/bin/python tools/sync.py --yes
   ```

   1件ずつ判断したいときは引数なし（y/n/a/q）。保留分は次回また出る。
   `ループ` / `ループ終ms` 列は書き込み直前に sync が自動で生やす（`ensure_loop_columns`）。

6. **書いた後に `--dry-run` をもう一度回して 0件になったことを確認**し、再確認結果を報告する。
   アプリ側は `revalidateTag("notion")` を待たず最大でキャッシュ分だけ古い表示が残る。

## やらないこと

- 記号の不一致をエラーにしない。実機の値が唯一の正
- 位置だけ動いたもの（「位置のみ」）は通知止まり。書かない
- 削除を未確認のまま `--yes` しない
- 🎵Tracks / 📍Cues を手で直さない（機械が管理する鏡。次の同期で上書きされる）

## 初回セットアップ

トークンと database ID は `~/.config/rekord_graph/config.json`（`tools/config.py` が読む。data source ID とは別物）。
DB が無ければ `tools/setup_notion.py --parent <ページ> --write` で作る。手順は `README.md` の「セットアップ」。
